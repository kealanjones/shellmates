# Quality Gates — Shellmates

## 1) Vision Gate
- **Purpose:** Ensure alignment with core fantasy and north star.
- **Pass criteria:** Supports connection through play; no therapy framing.
- **Fail examples:** Feature reframes game as relationship evaluator.
- **Who reviews:** Studio Director + Lead Game Designer.

## 2) Couples Gate
- **Purpose:** Preserve couples-first positioning.
- **Pass criteria:** Mechanics are built for romantic pair context, not generic buddy mode.
- **Fail examples:** Progression assumes friendship-party model.
- **Who reviews:** Relationship Design Lead + Product/Design.

## 3) Relationship Safety Gate
- **Purpose:** Prevent coercive or harmful relationship dynamics.
- **Pass criteria:** No blame, no coercion, no forced deep prompts.
- **Fail examples:** “Your partner is waiting” pressure copy.
- **Who reviews:** Couples Safety Agent + QA Lead.

## 4) Tone Gate
- **Purpose:** Protect cute/silly/warm/romantic tone.
- **Pass criteria:** Magical, playful language with gentle tension.
- **Fail examples:** Clinical language or grim horror tone.
- **Who reviews:** Narrative Director + Tone Drift Reviewer.

## 5) Mobile Gate
- **Purpose:** Validate mobile-first quality.
- **Pass criteria:** Readable, touch-appropriate, safe-area compliant.
- **Fail examples:** Tiny text, unclear taps, notch clipping.
- **Who reviews:** Mobile UX Agent + QA.

## 6) Asynchronous Gate
- **Purpose:** Ensure async-first clarity.
- **Pass criteria:** Solo meaningful progress + dual-contribution main gates.
- **Fail examples:** Real-time co-op dependency for core progression.
- **Who reviews:** Asynchronous Systems Designer + Game Design.

## 7) Story Gate
- **Purpose:** Keep chapter structure and canon consistent.
- **Pass criteria:** My Path, Their Path, Tidegate, shared resolution present.
- **Fail examples:** One-sided chapter completion for main story.
- **Who reviews:** Narrative Director + Lore Consistency Agent.

## 8) Art Gate
- **Purpose:** Maintain readability and visual direction.
- **Pass criteria:** Pixel readability, expressive characters/lobsters, coherent UI style.
- **Fail examples:** Unreadable sprites or direction drift.
- **Who reviews:** Art Director + Pixel Art Standards Agent.

## 9) Technical Gate
- **Purpose:** Ensure implementation quality and constraint compliance.
- **Pass criteria:** Stable behaviour, clear architecture boundaries, deferred systems respected.
- **Fail examples:** Premature backend/account integration.
- **Who reviews:** Technical Director + QA Lead.

## 10) Scale Gate
- **Purpose:** Prevent uncontrolled content/system scaling.
- **Pass criteria:** Schema-driven small-batch process followed.
- **Fail examples:** Bulk content drops without review.
- **Who reviews:** Content Production + QA + Studio Direction.

## 11) Privacy Gate
- **Purpose:** Protect data boundaries.
- **Pass criteria:** No personal relationship data architecture without approval.
- **Fail examples:** Storing sensitive partner history without policy.
- **Who reviews:** Studio Director + Technical Director + Safety.

## 12) Build Gate
- **Purpose:** Ensure release candidate technical health.
- **Pass criteria:** Build stability and core flow integrity.
- **Fail examples:** Frequent crashes, save corruption.
- **Who reviews:** Engineering + QA.

## 13) Review Gate
- **Purpose:** Ensure governance compliance before merge.
- **Pass criteria:** PR template complete, risks noted, decisions logged where needed.
- **Fail examples:** Missing acceptance criteria or unresolved blockers.
- **Who reviews:** PR reviewers + Studio Director delegate.
