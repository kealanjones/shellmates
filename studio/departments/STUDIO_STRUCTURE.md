# Studio Structure — AI-Native Operating Model

## Department Overview

### 1) Studio Direction
- **Purpose:** Maintain vision integrity and milestone focus.
- **Owns:** North star, scope arbitration, final go/no-go calls.
- **Active:** Always.
- **Collaborates with:** All departments.
- **Must not decide alone:** Relationship safety policy changes without Relationship Design and QA input.

### 2) Game Design
- **Purpose:** Define core loops, progression logic, and player motivation.
- **Owns:** Core mechanics, resource flows, chapter loop structure.
- **Active:** Milestone 0 onward.
- **Collaborates with:** Relationship Design, Narrative, Mobile UX, Technical.
- **Must not decide alone:** Any mechanic with relationship-risk implications.

### 3) Relationship Design
- **Purpose:** Ensure couples-first, non-coercive play patterns.
- **Owns:** Prompt design constraints, safety guardrails, emotional intensity framework.
- **Active:** Milestone 0 onward (mandatory early involvement).
- **Collaborates with:** Game Design, Narrative, QA.
- **Must not decide alone:** Platform-wide product positioning or monetisation decisions.

### 4) Narrative
- **Purpose:** Preserve tone, chapter structure, and world coherence.
- **Owns:** Episode themes, canon rules, narrative templates.
- **Active:** Milestone 0 onward.
- **Collaborates with:** Relationship Design, Game Design, Content Production.
- **Must not decide alone:** Changes to relationship safety boundaries.

### 5) Art
- **Purpose:** Deliver readable, expressive, cosy pixel direction.
- **Owns:** Visual language, style guides, art briefs, readability rules.
- **Active:** Milestone 0 planning; production scaling later.
- **Collaborates with:** Mobile UX, Narrative, Engineering.
- **Must not decide alone:** Major art-direction pivot without Studio Direction approval.

### 6) Engineering
- **Purpose:** Build robust, maintainable, mobile-first systems.
- **Owns:** Implementation patterns, system interfaces, technical risk management.
- **Active:** Planning in M0, implementation from M1.
- **Collaborates with:** Game Design, QA, Mobile UX.
- **Must not decide alone:** Backend/account/privacy architecture decisions.

### 7) Content Production
- **Purpose:** Scale chapters, prompts, rewards, and item sets once foundations are proven.
- **Owns:** Content throughput execution within approved schemas/pipelines.
- **Active:** Limited in M0/M1; scales after schema and gate validation.
- **Collaborates with:** Narrative, Relationship Design, QA.
- **Must not decide alone:** Large-batch generation without review approvals.

### 8) QA and Review
- **Purpose:** Detect drift, risk, regressions, and quality failures early.
- **Owns:** Test plans, quality gate validation, release readiness recommendations.
- **Active:** Milestone 0 onward (mandatory early involvement).
- **Collaborates with:** All departments.
- **Must not decide alone:** Product scope changes.

## Early-Phase Collaboration Rule
Early work must involve Studio Direction, Relationship Design, Game Design, Technical Direction, Mobile UX, and QA before scope expansion.

## Scaling Rule
Full Content Production must not scale until schemas are stable, vertical slice quality is proven, and review gates are consistently passed.
